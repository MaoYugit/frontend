### 1.3 响应式核心 API：`ref` 与 `reactive`

#### 一、 `ref`：全能型响应式接口

`ref` 的本质是将一个非响应式的数据，包装成一个具有 `value` 属性的**响应式对象（Impl）**。

**1. 基础用法与类型安全 (TS)**

```ts
import { ref } from 'vue'

// 1. 基本类型推导
const count = ref(0) // 推导为 Ref<number>

// 2. 复杂类型显示声明 (TS 实践)
interface User {
  name: string
  age: number
}
const user = ref<User>({ name: 'Alice', age: 25 })
```

**2. 核心机制：`.value` 的烦恼与自动脱靶**
*   **在逻辑层 (`<script>`)**：必须通过 `.value` 访问或修改。这是因为 JS 无法拦截基本类型的修改，Vue 必须将其封装在一个对象中，通过 `get/set value` 实现依赖收集和触发。
*   **在模板层 (`<template>`)**：Vue 会自动进行“解包（Unwrapping）”，你**不需要**写 `.value`。
*   **面试点**：*为什么 `ref` 定义的对象也要加 `.value`？* 
    *   因为 `ref` 内部会判断参数类型。如果是对象，它底层会自动调用 `reactive` 转为 Proxy，但最外层依然包裹着 `ref` 的壳。

---

#### 二、 `reactive`：深层响应式代理

`reactive` 只能接收**对象类型**（对象、数组、Map、Set），它返回的是该对象的 **Proxy 代理**。

**1. 深层响应式 (Deep Tracking)**
`reactive` 是深层的，修改嵌套极深的属性也会触发视图更新。
```ts
const state = reactive({
  nested: {
    count: 0
  },
  list: [1, 2]
})

const update = () => {
  state.nested.count++ // 触发更新
  state.list.push(3)    // 触发更新
}
```

**2. 致命陷阱：响应式丢失 (面试高频)**
这是新手最容易写出的 Bug，也是面试官必问的场景：

*   **陷阱 A：直接重新赋值**
    ```ts
    let info = reactive({ name: 'Vue' })
    // 错误操作：
    info = reactive({ name: 'Vite' }) 
    // 结果：原有的响应式引用断开了，页面不再更新。
    // 解决方案：使用 ref，或者修改 info 的属性 info.name = 'Vite'
    ```
*   **陷阱 B：解构赋值**
    ```ts
    const state = reactive({ count: 0 })
    let { count } = state 
    count++ // 错误：count 此时只是一个普通的 number，失去了与 state 的联系。
    // 解决方案：使用 toRefs (见 1.4 章节)
    ```

---

#### 三、 `ref` vs `reactive`：深度对比与选型

| 特性         | `ref`                                | `reactive`                 |
| :----------- | :----------------------------------- | :------------------------- |
| **适用类型** | 所有类型（基本+对象）                | 仅限对象类型               |
| **底层实现** | `Object.defineProperty` (value 属性) | `Proxy` 代理整个对象       |
| **访问方式** | 脚本中需 `.value`，模板中不需要      | 均不需要 `.value`          |
| **重新赋值** | 支持（修改 `.value`）                | **不支持**（会丢失响应式） |
| **解构**     | 不支持（解构后需手动处理）           | **不支持**（会丢失响应式） |

**资深开发建议 (Best Practice)：**
1.  **首选 `ref`**：为了代码一致性，绝大多数大厂规范（如 Vue 官方文档、Nuxt 团队）建议优先使用 `ref`。它虽然多写一个 `.value`，但能避免“响应式丢失”的心理负担，且类型推导更稳健。
2.  **慎用 `reactive`**：仅当一组数据在逻辑上是不可分割的整体（如表单聚合对象），且你确定不会对其进行替换或解构时，才使用 `reactive`。

---

#### 四、 底层原理浅析 (面向面试)

**问：Vue 3 如何知道数据变了？**
*   **`ref` (基本类型)**：通过 `class` 的 `get value()` 和 `set value()`。当触发 `set` 时，通知相关的副作用函数（Effect）重新执行。
*   **`reactive`**：使用 ES6 `Proxy`。它通过 `track` 收集当前属性的依赖，通过 `trigger` 通知依赖更新。
*   **优势**：相比 Vue 2 的 `Object.defineProperty`，`Proxy` 可以监听**数组下标修改**和**对象新增属性**，性能更好且解决了 Vue 2 的遗留缺陷。
