### 1.1 开发环境搭建与必备工具

在 Vue 3 开发中，环境配置的目标不仅是“能运行”，而是要实现**类型检查、代码规范自动化**以及**响应式链路的可视化追踪**。

---

#### 一、 编辑器环境：VS Code 深度配置

VS Code 是 Vue 3 开发的标准工具。为了配合 Vue 3 的 Composition API 和 TypeScript，必须完成以下配置：

**1. 核心插件安装**
*   **Vue - Official (原 Volar)**：这是 Vue 3 的官方插件。
    *   **核心功能**：提供 `.vue` 文件的语法高亮、智能补全、类型检查。
    *   **面试考点**：*为什么 Vue 3 不再使用 Vetur？* 因为 Vetur 无法很好地支持 Composition API 的 TS 类型推导，而 Volar 针对 Vue 3 的响应式转换（如 `ref` 的自动脱靶）做了原生支持。
*   **ESLint**：实时检测代码中的潜在错误和风格问题。
*   **Prettier - Code formatter**：代码格式化工具，确保团队代码风格高度统一。

**2. 生产力配置（Settings.json）**
为了实现“保存即修复”，建议在 VS Code 的配置文件中加入以下逻辑，避免面试中常被问到的“如何保持团队代码风格一致”的问题：
```json
{
  "editor.formatOnSave": true, 
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit" 
  },
  "vue.server.hybridMode": true // 开启混合模式以获得极速类型检查
}
```

---

#### 二、 调试利器：Vue Devtools

Vue Devtools 不仅仅是查看组件树，它是排查**响应式失效**和**性能瓶颈**的核心工具。

**1. 安装与激活**
*   在 Chrome/Edge 扩展商店安装 **Vue.js devtools** (确保版本支持 Vue 3)。
*   在开发环境下，按下 `F12` 看到 `Vue` 选项卡即为成功。

**2. 核心功能与实战技巧（面试常问）**
*   **Component Tree (组件树)**：
    *   **排查范围**：点击组件可查看该组件接收的 `props`、定义的 `setup` 变量、`computed` 属性。
    *   **实时修改**：你可以直接在面板修改 `ref` 的值，观察页面是否触发响应式更新，用于快速验证逻辑。
*   **Timeline (时间轴/追踪)**：
    *   **响应式追踪**：这是 Vue 3 独有的。当数据发生变化但页面没动时，查看 `Mouse` 或 `Component Events`，看 `Reactive Effect` 是否被触发。
    *   **性能分析**：记录组件渲染耗时，定位哪个组件导致了掉帧。
*   **Inspector (选择器)**：
    *   点击浏览器左上角的“箭头”图标再点击页面元素，可以直接定位到对应的 Vue 组件源代码，在大项目中寻找组件位置极快。

#### 三、 现代开发流：Node.js 与 Vite

虽然本节重点是工具，但必须明确：**Vue 3 官方推荐使用 Vite 作为构建工具**。

1.  **Node.js 版本**：确保在 `18.3` 或更高版本，以支持最新的前端生态。
2.  **创建命令**：
    ```bash
    npm create vue@latest
    ```
    在该流程中，勾选 `ESLint` 和 `Prettier`，它会自动帮你生成上述插件所需的配置文件（如 `.eslintrc.cjs`）。

---

#### 四、 面试要点小结

1.  **Volar (Vue - Official) 的作用？** 它是 Vue 3 的语言服务，解决了 TS 在 `.vue` 文件中的类型推断问题。
2.  **如何定位响应式数据不更新的问题？** 
    *   首先通过 **Vue Devtools** 的组件面板检查数据值是否符合预期；
    *   其次利用 **Timeline** 面板查看是否有对应的渲染追踪（Render Tracked）或触发（Render Triggered）。
3.  **ESLint 与 Prettier 冲突怎么办？** 实际开发中通过 `eslint-config-prettier` 禁用掉与 Prettier 冲突的 ESLint 规则，让 ESLint 负责逻辑错误，Prettier 负责视觉格式。
