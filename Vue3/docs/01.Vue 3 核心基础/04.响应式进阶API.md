### 1.4 响应式进阶 API

#### 一、 `toRef` 与 `toRefs`：响应式丢失的“终结者”

在 1.3 中我们提到，直接解构 `reactive` 对象会导致响应式丢失。`toRefs` 和 `toRef` 就是为了解决这个问题，它们能将 `reactive` 对象的属性**保持关联地**转换为 `ref`。

**1. `toRefs` (批量转换)**
*   **场景**：当你想从一个 Composable 函数（组合式函数）返回一个响应式对象，并希望在组件中直接解构使用时。
*   **原理**：它会遍历对象的所有属性，每个属性都转换成一个 `ref`，这些 `ref` 与源对象属性**双向绑定**。

```ts
import { reactive, toRefs } from 'vue'

const state = reactive({
  count: 0,
  name: 'Vue3'
})

// 解构后依然是响应式的 Ref
const { count, name } = toRefs(state) 

// 修改 count.value，state.count 也会变
count.value++ 
```

**2. `toRef` (单个转换)**
*   **场景**：只需要将对象中的某一个属性提取出来。
*   **语法**：`toRef(object, 'key')`

---

#### 二、 `shallowRef` 与 `shallowReactive`：性能优化利器

Vue 默认的响应式是“深层的”，这意味着如果你有一个 10000 层的对象，Vue 会递归地将其所有属性都变成响应式。这在处理**大数据集**或**第三方复杂实例**时会导致严重的卡顿。

**1. `shallowRef` (浅层 ref)**
*   **核心逻辑**：只追踪 `.value` 这一层的变化。如果 `.value` 对应的对象内部属性变了，Vue **不会**触发更新。
*   **实战场景**：
    *   **大型 List**：如从后端获取的数万条监控日志，只展示不修改内部。
    *   **第三方实例**：如 Echarts 实例、地图 OpenLayers 实例、三维渲染器（Three.js）。这些实例自带复杂的内部逻辑，交给 Vue 监听会导致页面瞬间崩溃。

```ts
import { shallowRef } from 'vue'

const chartInstance = shallowRef(null)

// 优化写法：只有替换整个对象才会触发视图更新
const updateData = (newData: any) => {
  chartInstance.value = newData 
}
```

**2. `shallowReactive` (浅层 reactive)**
*   **核心逻辑**：只有对象的第一层属性是响应式的。

---

#### 三、 `readonly` 与 `shallowReadonly`：数据“防弹衣”

在多人协作或大型应用中，我们经常需要实现**单向数据流**：父组件提供数据，子组件只能看，不能改。

**1. `readonly` (深层只读)**
*   接收一个对象（普通的或响应式的），返回一个原始对象的 **只读代理**。
*   **面试点**：如果传入的是 `ref`，修改原始 `ref` 依然会触发 `readonly` 代理的更新，但直接改 `readonly` 代理会报错。

```ts
import { ref, readonly } from 'vue'

const original = ref(0)
const copy = readonly(original)

original.value++ // OK, copy 也会变成 1
// copy.value++  // 报错！Set operation on key "value" failed: target is readonly.
```

**2. 实战架构建议**：
在 `provide / inject` 跨组件通信时，强烈建议将数据用 `readonly` 包裹后再传给后代，防止后代组件“越权”修改全局状态，导致 Bug 难以追踪。

#### 四、 面试避坑指南（资深拆解）

**1. `toRef` 和 `ref` 有什么区别？**
*   `ref(state.count)`：是**拷贝**。修改新的 ref，原 `state.count` 不会变。
*   `toRef(state, 'count')`：是**引用**。修改新的 ref，原 `state.count` **同步变化**。

**2. `shallowRef` 里的数据变了，但我现在强行想让页面更新一次，怎么办？**
*   **方案**：使用 `triggerRef(myShallowRef)`。它可以手动强制触发与浅层 ref 关联的副作用函数。

**3. 什么时候该用 `shallowRef`？**
*   当你发现某个组件渲染大数据量列表时非常卡顿。
*   当你接入第三方库实例（如 `new Map()` 或 `new Swiper()`）时。
