### 一、 变量、作用域与现代模式（对应：代码结构、"use strict"、变量、JavaScript特性）

1. `var`、`let` 和 `const` 之间有什么区别？请从变量提升、块级作用域、重复声明和暂时性死区（TDZ）等维度进行说明。

   var 和 let 用于定义变量，const 用于定义常量，现在我们一般使用 let 而不使用 var。三者都会有变量提升，但是对于在使用var之前使用一个变量的话，值是undefined；而对于 let 和 const 来讲存在暂时性死区TDZ，在定义之前使用会报ReferenceError; var没有块级作用域，let和const有块级作用域，var可以重复声明，最新值是后声明的值，其他两个不允许重复声明，const也不能重新赋值。

2. 什么是变量提升（Hoisting）？函数声明的提升和变量（`var`）声明的提升有什么区别？

   变量提升就是js在代码执行钱的编译阶段，将当前作用域中的所有变量的声明注册到该作用域顶部的机制。函数声明的提升可以正常使用该函数，但是var只提升声明，不提升值。

3. 什么是“暂时性死区”（Temporal Dead Zone）？它是如何产生的？

   暂时性死区是指let 和 const 在作用域中定义变量的位置到作用于顶部的位置。产生机制是js在编译js代码的时候会把变量声明提升到作用于顶部，但是不提升变量的值，在此区间访问变量会报错，也就产生了TDZ。

4. 如果修改一个用 `const` 声明的对象（或数组）的属性，会报错吗？为什么？如果想让一个对象完全不可变，应该如何处理？

   只修改属性不会报错。因为对象存储的是引用地址，只要地址值不变就可以。如果想让一个对象完全不可变可以用`Object.freeze(obj)`,并开启严格模式；

5. 为什么现代 JavaScript 开发中通常建议使用严格模式（`"use strict"`）？如何在脚本或函数中开启它？

   之所以推荐使用严格模式是因为严格模式下对于像未使用let\cosnt\var声明的变量会报错，不允许使用诸如with这样的一些语句，有助于性能优化，想要开启严格模式只需要在脚本或者函数最顶部添加“use strict”; 即可。

6. 在严格模式（`"use strict"`）下，相比于非严格模式，有哪些常见的限制和行为变化（例如未声明变量赋值、`this` 的指向等）？

   在非严格模式下，对只读属性、不可扩展对象或者删除不可删除属性是操作会静默失败，但是严格模式下会抛出；非严格模式下不适用let var const声明一个变量会自动创建一个全局对象，严格模式下会报错；非严格模式下独立调用的函数的this指向全局对象，严格模式下是undefined；非严格模式下。函数名可以重复，后者覆盖前者，严格模式下不行；严格模式下禁用with语句和arguments.callee，有助于性能优化也更安全；严格模式下保留字的限制更加严格。

7. 当我们在一个内层作用域中声明一个与外层作用域同名的变量时，会发生什么？这称为什么现象？

   内层作用域会覆盖掉外层作用域的同名变量；这被称为变量遮蔽。

8. 如果在声明变量之前尝试读取一个从未被声明的变量，与读取一个使用 `let` 声明但在后面才初始化的变量，控制台的报错信息有何不同？

### 一、 变量、作用域与现代模式

#### 1. `var`、`let` 和 `const` 之间有什么区别？请从变量提升、块级作用域、重复声明和暂时性死区（TDZ）等维度进行说明。
* **块级作用域：** `var` 没有块级作用域（只有全局作用域和函数作用域）；`let` 和 `const` 拥有块级作用域（由 `{}` 包裹的区域）。
* **变量提升：** `var` 声明的变量会提升到当前作用域的顶部，并初始化为 `undefined`；`let` 和 `const` 声明的变量也会被提升，但不会被初始化，在声明行执行前访问会触发错误。
* **暂时性死区（TDZ）：** 由于 `let` 和 `const` 存在提升但不初始化的特性，在块级作用域开始到变量声明语句执行完毕之间的区域，被称为暂时性死区，在此区域访问该变量会抛出 `ReferenceError`。
* **重复声明：** 在同一作用域下，`var` 允许重复声明同一个变量；而 `let` 和 `const` 不允许，否则会抛出 `SyntaxError`。
* **重新赋值：** `var` 和 `let` 声明的是变量，允许重新赋值；`const` 声明的是只读常量，一旦声明必须立即初始化，且后续不允许重新赋值。

---

#### 2. 什么是变量提升（Hoisting）？函数声明的提升和变量（`var`）声明的提升有什么区别？
* **变量提升：** 是指 JavaScript 引擎在执行代码前的编译阶段，会将当前作用域内所有变量和函数的声明“移动”到当前作用域顶部的行为（实际上是注册在当前作用域的词法环境中）。
* **两者的区别：**
  * **函数声明提升：** 函数声明会被完整地提升，包括函数的定义体。因此，在函数声明之前可以正常调用该函数（即“函数前置调用”）。
  * **`var` 声明提升：** `var` 只会提升变量的声明，而不会提升赋值操作。在声明并赋值的语句之前访问该变量，其值会是 `undefined`。
  * **优先级：** 如果同名的函数声明和 `var` 变量声明同时存在，函数声明的提升优先级高于变量声明。

---

#### 3. 什么是“暂时性死区”（Temporal Dead Zone）？它是如何产生的？
* **概念：** 暂时性死区（TDZ）是指在一个作用域（块级作用域）内，从该作用域的开始位置，到 `let` 或 `const` 变量声明语句被实际执行到的这行代码之间，该变量处于不可用的状态。
* **产生机制：** 
  JavaScript 引擎在进入当前作用域并进行“编译”时，会发现 `let` 或 `const` 声明的变量，并将其放入作用域中。但与 `var` 自动初始化为 `undefined` 不同，`let` / `const` 此时处于**未初始化（Uninitialized）**状态。只有当代码执行流实际到达声明变量的那一行时，初始化才算完成。在初始化完成之前尝试访问该变量，引擎就会抛出 `ReferenceError`。

---

#### 4. 如果修改一个用 `const` 声明的对象（或数组）的属性，会报错吗？为什么？如果想让一个对象完全不可变，应该如何处理？
* **不会报错。** 
  因为 `const` 保证的不是变量的值不能改动，而是变量指向的**内存地址（引用）**不能改动。对于对象或数组等引用类型，其属性的增删改并没有改变该对象在堆内存中的地址，因此 `const` 允许这种修改。
* **完全不可变的解决方案：**
  1. **浅冻结：** 可以使用 `Object.freeze(obj)`，它会阻止向对象添加新属性、删除旧属性以及修改已有属性的描述符和值。
  2. **深冻结（彻底不可变）：** 因为 `Object.freeze` 是浅层的，如果对象内部嵌套了其他对象，内层对象仍可修改。需要通过递归函数对对象的每一个嵌套对象属性都调用 `Object.freeze()`：
     ```javascript
     function deepFreeze(obj) {
       Object.freeze(obj);
       Object.keys(obj).forEach(key => {
         if (typeof obj[key] === 'object' && obj[key] !== null) {
           deepFreeze(obj[key]);
         }
       });
     }
     ```

#### 5. 为什么现代 JavaScript 开发中通常建议使用严格模式（`"use strict"`）？如何在脚本或函数中开启它？
* **推荐原因：**
  * **消除怪异行为：** 将一些 JS 中不合理、静默失败的操作转为显式报错（如向只读属性赋值）。
  * **增强安全性：** 禁用一些不安全或混乱的特性（如 `with` 语句、严格限制 `eval` 作用域）。
  * **防止意外全局变量：** 强制要求变量必须声明后才能使用，避免因拼写错误导致意外创建全局变量。
  * **利于引擎优化：** 严格模式下的代码更具确定性，现代 JS 引擎（如 V8）更容易对其进行编译优化，提高执行效率。
  * **为未来做准备：** 预留了更多未来的保留字。
* **开启方式：**
  * **全局/脚本级：** 在脚本文件的第一行加入 `"use strict";`。
  * **函数级：** 在函数的函数体第一行加入 `"use strict";`。
  * *(注：在 ES6 Module 和 Class 内部，默认就是严格模式，无需手动声明)*。

#### 6. 在严格模式（`"use strict"`）下，相比于非严格模式，有哪些常见的限制和行为变化（例如未声明变量赋值、`this` 的指向等）？
1. **禁止意外创建全局变量：** 未经 `let/const/var` 声明直接赋值变量（如 `x = 10`），在严格模式下会抛出 `ReferenceError`（非严格模式下会自动挂载到全局对象）。
2. **`this` 指向的变化：** 在全局或独立调用的普通函数中，`this` 默认指向 `undefined`，而在非严格模式下指向全局对象（`window` / `global`）。
3. **静默失败变显式报错：** 尝试删除不可配置（non-configurable）的属性、修改只读（writable: false）属性或给不可扩展（non-extensible）的对象新增属性时，严格模式会直接抛出 `TypeError`。
4. **禁止重复的函数参数名：** 严格模式下，函数形参重名（如 `function foo(a, a) {}`）会报语法错误 `SyntaxError`。
5. **禁用 `with` 语句：** 严格模式下使用 `with` 会直接导致编译错误。
6. **限制 `eval` 的作用域：** `eval` 内部声明的变量不再漏出到外部作用域中。
7. **禁用 `arguments.callee`：** 无法再通过它引用当前正在执行的函数，保护了调用栈。

---

#### 7. 当我们在一个内层作用域中声明一个与外层作用域同名的变量时，会发生什么？这称称为现象？
* **会发生什么：** 在内层作用域中，外层的同名变量将被“隐藏”或无法直接访问。在该内层作用域中对该变量名的一切读写操作，都只作用于内层新声明的变量。
* **现象名称：** 这被称为**变量遮蔽**（Variable Shadowing，也译作作用域屏蔽）。

---

#### 8. 如果在声明变量之前尝试读取一个从未被声明的变量，与读取一个使用 `let` 声明但在后面才初始化的变量，控制台的报错信息有何不同？
* **读取从未声明的变量：**
  * 报错信息：`Uncaught ReferenceError: [变量名] is not defined`
  * 解释：引擎在任何作用域链上都找不到该变量的标识符。
* **读取声明了但未初始化（在 TDZ 中）的 `let` 变量：**
  * 报错信息：`Uncaught ReferenceError: Cannot access '[变量名]' before initialization`
  * 解释：引擎知道该变量的存在（由于提升），但它目前处于暂时性死区（未初始化状态），在此阶段不允许访问。
