# JavaScript 数值存储机制解析

在 JavaScript 中，无论是整数（如 `5`、`100`）还是小数（如 `0.1`、`3.14`），在内存里都是用**同一种格式**存储的，即 **IEEE 754 双精度浮点数（Double Precision）**格式。这种格式一共占用 **64 个二进制位（bits）**。

你可以把这 64 位想象成一排排好的 **64 个小格子**，每个格子里面只能放 `0` 或者 `1`。

### 64位格子的整体布局

这 64 个格子被固定分成了三组，各自承担不同的工作：

```text
 ┌───┬───────────────────────┬────────────────────────────────────────────────────────┐
 │ s │       Exponent        │                        Fraction                        │
 └───┴───────────────────────┴────────────────────────────────────────────────────────┘
 1 bit       11 bits                                  52 bits
 符号位       指数位                                    尾数位
```

1. **符号位（Sign）** —— 占用 **1 个格子**。
   * 负责决定数字是**正数**还是**负数**。
2. **指数位（Exponent）** —— 占用 **11 个格子**。
   * 负责决定**小数点的位置**（即科学计数法里的底数幂次，如 10^3 中的 3）。
3. **尾数位（Fraction / Mantissa）** —— 占用 **52 个格子**。
   * 负责记录数字的**具体有效数字**。

这三组格子加起来：1 + 11 + 52 = 64 位。

---

## 一、 工作原理拆解

### 1. 符号位（第 1 个格子）
* 如果格子里是 **`0`**：代表**正数**。
* 如果格子里是 **`1`**：代表**负数**。

### 2. 尾数位（52位）与“省空间”的“隐式 1”
计算机在内部使用**二进制科学计数法**来表示数字，其标准格式为：
$$
\pm 1.xxxxxx \times 2^{\text{指数}}
$$
在二进制的世界里，除了 0 之外，任何数字的科学计数法开头**必定是 `1.`**（因为二进制只有 `0` 和 `1`，且首位不能为 `0`）。

既然开头的那个 `1.` 雷打不动，计算机科学家做了一个聪明的决定：
* **只在 52 个尾数格子里存小数点后面的部分（即 `xxxxxx`）。**
* **开头的 `1.` 直接省略不存**，只有当计算机取出数据计算时，才在底层自动把 `1.` 补回去。

**例子：**
假设二进制数科学计数法写出来是 
$$
1.01_2 \times 2^1
$$

* 尾数部分我们只存小数点后的 **`01`**。
* 剩下的 50 个格子用 `0` 填满。
* 实际存入尾数位的数据是：`01000000...00`（共52位）。

> **优势：** 虽然只用了 **52** 个格子的物理空间，但因为省掉了默认的 `1.`，实际上获得了 **53 位**的数值精度。

### 3. 指数位（11位）与“偏移量 1023”
11 个指数位可以表示的无符号整数范围是 `0` 到 `2047`（即二进制的 `00000000000` 到 `11111111111`）。但科学计数法的指数往往有负数（比如表示微小的小数时，指数为负）。

为了在不增加符号位的前提下表示负指数，计算机引入了**偏移量（Bias）**机制：
$$
\text{格子里存的数值（无符号）} = \text{真实指数} + 1023
$$

* **想表示真实指数 `0`**：格子里存 0 + 1023 = 1023（二进制：`01111111111`）
* **想表示真实指数 `1`**：格子里存 1 + 1023 = 1024（二进制：`10000000000`）
* **想表示真实指数 `-1`**：格子里存 -1 + 1023 = 1022（二进制：`01111111110`）

## 二、 特殊状态下的格子组合

11 位指数位的最大值 `2047`（全 `1`）和最小值 `0`（全 `0`）是具有特殊含义的预留值：

| 指数位状态 (11位) | 尾数位状态 (52位) | 符号位 (1位) | 在 JS 中代表的含义                 |
| :---------------- | :---------------- | :----------- | :--------------------------------- |
| **全为 1** (2047) | **全为 0**        | `0`          | `+Infinity`（正无穷大）            |
| **全为 1** (2047) | **全为 0**        | `1`          | `-Infinity`（负无穷大）            |
| **全为 1** (2047) | **不全为 0**      | 任意         | `NaN`（非数字，表示无效计算）      |
| **全为 0**        | **全为 0**        | `0`          | `+0`（正零）                       |
| **全为 0**        | **全为 0**        | `1`          | `-0`（负零）                       |
| **全为 0**        | **不全为 0**      | 任意         | **非规格化数**（极小的渐进下溢数） |

> **关于 NaN 的冷知识：**
> 只要尾数位“不全为 0”就代表 `NaN`，这意味着在底层内存里，有 2^{52} - 1 种不同的二进制组合都可以表示 `NaN`。但在 JS 运行环境中，它们在应用层都会被一视同仁地当作同一个 `NaN`。

## 三、 JS 的边界值是如何算出来的？

### 1. 最大的数（Number.MAX_VALUE）

如果我们要用 64 个格子拼出一个**绝对值最大**的正数，格子应该这样填：

* **符号位**：填 `0`（正数）。
* **尾数位**：全部填满 `1`。
  * 加上隐藏的 `1.`，尾数实际为：$1.1111...1_2$（小数点后有 52 个 1），这个数在数学上无限接近于 **`2`**。
* **指数位**：
  * 11 位能表达的最大值是 2047，但 2047 预留给了 `Infinity`和`NaN`。
  * 因此，能用来表示正常数字的最大指数存储值是 **`2046`**。
  * 还原真实指数：2046 - 1023 = **`1023`**。

#### 最终计算：
$$
\text{最大值}  = (2 - 2^{-52}) \times 2^{1023} = 2^{1024} - 2^{971} \approx 2 \times 2^{1023} = 2^{1024}
$$

换算成十进制大约是：
$$
1.79 \times 10^{308}
$$
在 JavaScript 中，这个极限值被称为 **`Number.MAX_VALUE`**。任何比它还大的计算结果都会溢出，被 JS 判定为 **`Infinity`**。

---

### 2. 最小的数（最接近 0 的正数）

想要表示无限接近于 0 的正数，这里分为两种情况：

#### 情况 A：正常状态下的最小值（规格化数）
* **符号位**：填 `0`。
* **尾数位**：全部填 `0`（加上隐式 `1.`，尾数实际等于 `1`）。
* **指数位**：
  * 除去被保留的 `0`，最小的指数存储值是 **`1`**。
  * 还原真实指数：1 - 1023 = **`-1022`**。

#### 最终计算：
$$
1 \times 2^{-1022} \approx 2.22 \times 10^{-308}
$$



---

#### 情况 B：极限状态下的绝对最小值（非规格化数）
如果想表示比 2..22 * 10^-308 更小的数，需要使用**非规格化数（Subnormal Number）**规则。
当指数位**全填 `0`** 时，IEEE 754 规定：

1. **开头的“隐式 1”降格为“隐式 0”**（即尾数变成了 `0.xxxxxx`）。
2. **真实指数固定为 `-1022`**（而不是 `-1023`，这是为了平滑衔接上述情况 A 的分界点）。

在这个极限规则下，我们把 52 位尾数的**最后一位填 `1`**，其余 51 位全部填 `0`：
* 此时尾数实际上等于：2^-52。

#### 最终计算：
$$
\text{绝对最小值} = 2^{-52} \times 2^{-1022} = 2^{-1074}
$$

换算成十进制大约是：
$$
5 \times 10^{-324}
$$
在 JavaScript 中，这个极限值被称为 **`Number.MIN_VALUE`**。如果一个正数比这个值还要小，JS 在内存中就再也无法用二进制格子表示它，只能将其强制判定为 **`0`**（渐进下溢）。
